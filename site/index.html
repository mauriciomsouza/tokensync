Catch design-token drift
before it ships.

A designer changes a color in Figma. Nobody updates the CSS. A month later the product has two sources of truth. tokensync compares Figma variables with the tokens in your code, shows exactly what drifted, and can open a pull request to fix it.

Try it in the browser npx tokensync-cli check
  • Figma Variables with modes and aliases
  • CSS, DTCG, Tailwind on the code side
  • ΔE 2000 perceptual color diffs
  • Exit 1 on drift for CI
  1. 01

    Read

    Figma variables from the REST API or an export. Aliases resolved per mode, names normalized.

  2. 02

    Compare

    Against CSS custom properties, DTCG JSON or a Tailwind theme. Colors compared perceptually.

  3. 03

    Report

    Terminal table, JSON, a sticky PR comment, or a single-file HTML report with swatches.

  4. 04

    Sync

    Rewrite the code tokens to match Figma, keeping comments, units and key order.

Playground

Pre-filled with Aurora, a fictional design system with intentional drift. Edit either side and the report updates live. Runs entirely in your browser.

In CI, on every pull request

The GitHub Action runs tokensync check, posts one sticky comment with the drift report, and can open a “sync tokens” PR on a schedule. See the full example report. 

- uses: mauriciomsouza/tokensync@v0
  with:
    figma-file-key: ${{ vars.FIGMA_FILE_KEY }}
    figma-token: ${{ secrets.FIGMA_TOKEN }}
    comment: true
